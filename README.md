# RegexEngine
A regular expression engine built from scratch in Haskell: Parser → NFA → DFA → Matcher.

## Overview
This project implements a regular expression engine end to end. It takes a regex as a string and builds an AST from it.The AST is then compiled into a nondeterministic finite automaton (NFA) using Thompson's construction. The NFA can optionally be transformed into a DFA via the subset construction, which can then be
minimized into the smallest equivalent DFA. Finally, the matcher simulates the automaton on the input and returns a boolean indicating whether
the regex matches the whole input string. Together, this illustrates the classical correspondence between regular expressions, NFAs, and DFAs.

## Build & Testing
The project was built with Stack

```sh
stack build      # compile the library, executable, and test suite
stack test       # run the full test suite (HSpec unit/e2e + QuickCheck properties)
stack run -- ... # run the engine on a pattern and an input (see Usage Examples)
```
The test suite covers unit tests (parser results, individual constructors), end-to-end
matching on curated patterns, and four property-based checks: NFA matcher vs DFA matcher,
the matcher against `Text.Regex.TDFA`, a `parse . pretty` round-trip, and the minimized DFA
vs the unminimized DFA.

## Architecture
The engine is split into single-responsibility modules, mirroring the regex → NFA → DFA pipeline:

- **`AST`** — the `Regex` data type (`Empty`, `Lit`, `Concat`, `Union`, `Star`) and a `pretty`
  printer that renders an AST back into a fully-parenthesized regex string.
- **`Parser`** — a combinator parser built on `StateT String []`. Exposes `parse` (returning
  `Maybe Regex`) and `parseWithErr` (returning `Either` an error with the position of the failure).
  Bounded repetition `{n,m}` is desugared here into existing `Concat`/`Union`/`Star` nodes, so it
  requires no changes to the automaton.
- **`NFA`** — Thompson's construction. Compiles a `Regex` into an NFA whose edges are
  `(Int, Maybe Char, Int)` triples, where `Nothing` denotes an ε-transition. Fresh state ids are generated by a counter carried in the State monad.
- **`Match`** — simulates the NFA on an input string, keeping track of which states are active as it reads each character, and reports whether the whole input is accepted.
- **`DFA`** — the subset construction (`buildDFA`) turning an NFA into a DFA, plus DFA
  minimization (`minimizeDFA`) that merges indistinguishable states via table-filling. Both
  the plain and minimized DFA can run the input through a shared `runDFA`.
- **`Main`** — a command-line interface exposing all three engines: NFA (default), DFA (`--dfa`),
  and minimized DFA (`--min`, which also prints a before/after state-count comparison).

## Usage Examples
The CLI takes a pattern and an input string. Without a flag it uses the NFA engine;
`--dfa` uses the DFA; `--min` uses the minimized DFA and prints a state-count comparison.

```sh
$ stack run -- "(a|b)*c" "ababc"
pretty AST: (((a|b))*c)
MATCH!

$ stack run -- "(a|b)*c" "abab"
pretty AST: (((a|b))*c)
NO MATCH!

$ stack run -- --dfa "a{2,3}" "aaa"
pretty AST: (aa(a|))
MATCH!

$ stack run -- --min "(a|b)*c" "ababc"
pretty AST: (((a|b))*c)
DFA size comparison:
  subset construction : 5 states
  after minimization  : 3 states
  reduced by          : 2 states
MATCH!
```

When a pattern is invalid, the parser reports the position of the failure instead of crashing:

```sh
$ stack run -- "a{2,1}" "aa"
Parse error at position 1:
a{2,1}
 ^
```

## Grammar
The parser implements the following grammar, with the conventional precedence
(alternation binds loosest, postfix operators bind tightest):

```
regex   ::= term ('|' term)*
term    ::= factor*
factor  ::= atom postfix*
postfix ::= '*' | '+' | '?' | '{' bound '}'
bound   ::= num | num ',' num | num ','
atom    ::= '(' regex ')' | '\' char | literal
num     ::= digit+
```

Supported syntax:

| Syntax        | Meaning                                   |
| ------------- | ----------------------------------------- |
| `a`           | literal character                         |
| `ab`          | concatenation                             |
| `a\|b`        | alternation                               |
| `a*`          | zero or more                              |
| `a+`          | one or more                               |
| `a?`          | zero or one                               |
| `a{n}`        | exactly `n` repetitions                   |
| `a{n,m}`      | between `n` and `m` repetitions           |
| `a{n,}`       | `n` or more repetitions                   |
| `(...)`       | grouping                                  |
| `\c`          | escaped metacharacter

## Tests
Run with `stack test`. The suite has three layers:

- **Unit tests** — parsing individual constructors and operators (including `{n}`/`{n,m}`/`{n,}`
  and rejected malformed bounds), and matching each constructor against trivial inputs.
- **End-to-end tests** — curated patterns paired with matching and non-matching strings,
  including pathological cases like `(a*)*` on long inputs (which an automaton handles without
  the exponential blow-up of a backtracking engine).
- **Property-based tests (QuickCheck)** — on random regexes and inputs: the NFA matcher agrees
  with the DFA matcher, the matcher agrees with `Text.Regex.TDFA`, `parse . pretty` round-trips,
  and the minimized DFA agrees with the unminimized DFA.
